# Stage 5: Tracking — Architecture Design Notes

**Date:** Mar 05, 2026
**Status:** Parked — to be built in a future sprint

---

## Core Design Decision

**Signal Configuration:** offering-scoped (one config per Offering Brain, applied across all campaigns)
**Scan Run:** campaign-scoped (each campaign has its own scan cadence and results view)

This separation means: configure signals once per offering, run scans per campaign. The "what to look for" is defined by the offering brain; the "where to look" is defined by the campaign.

---

## Data Model (Three New Entities)

| Entity | What it represents | Scope |
| :--- | :--- | :--- |
| **Signal Configuration** | Which signals to watch and their weight | Per Offering Brain |
| **Scan Run** | A single execution of the tracking engine | Per Campaign |
| **Signal Hit** | A specific signal detected for a specific company in a specific scan | Per Company × Scan |

The `urgency_score` on each company becomes a *computed* field derived from the most recent signal hits, weighted by the signal configuration. Signal hits are stored permanently with timestamps to enable urgency decay over time.

## Signal List (Agreed)

| Signal | Source | Urgency Weight | Notes |
| :--- | :--- | :--- | :--- |
| **Hiring in production / manufacturing / engineering roles** | Indeed / Glassdoor / company careers (via Grok) | **High** | Grok-powered job posting search, offering-context-aware. NOT LinkedIn (blocks scraping). Interpret in context of offering brain — e.g. "hiring PCB Designer" → needs assembly partner |
| **Funding round announced** | News (via Grok) | **High** | Keep as-is |
| **New leadership (CTO, COO, VP Ops, VP Manufacturing)** | News / LinkedIn announcements (via Grok) | **High** | New leaders buy new things |
| **Expansion / new facility / new plant** | News (via Grok) | **High** | Promoted from Medium — physical expansion is a direct outsourcing trigger |
| **Revenue growth / record results announced** | News (via Grok) | **Medium** | Added signal — companies announcing strong results are investing, not cutting |
| **Technology migration / ERP / MES upgrade** | News / job postings (via Grok) | **Medium** | Keep |
| **Regulatory compliance deadline** | Industry news (via Grok) | **Medium** | Offering-brain-specific — only relevant for certain sectors |
| **Conference / trade show participation** | Conference sites | **Low** | Also an import source — creates an interesting loop with Conference Import feature |
| **General company news** | News (via Grok) | **Low** | Catch-all |

## Key Architectural Principle: Signal Interpretation, Not Just Detection

Grok should not just *detect* signals — it should *interpret* them in the context of the offering brain.

The prompt to Grok must include the offering description so it can assess relevance, not just presence. A funding round at a software company means something different than at a contract manufacturer.

Each Signal Hit should store:
- Signal type
- Raw evidence (headline, URL, date)
- **One-sentence relevance assessment** generated by Grok at scan time (e.g. "Funding round of €12M announced March 3 — likely to accelerate production scale-up given their hardware product roadmap")
- Urgency weight at time of detection

## UI Design

### Offering Brain page — new "Signal Configuration" tab
- Toggle each signal type on/off
- Set weight (High / Medium / Low)
- Set scan cadence (Daily / Weekly / Manual)
- Set minimum fit score threshold for inclusion in scans

### Campaign results view — enhanced
- New sort mode: **Fit × Urgency** (infrastructure already exists)
- Companies with recent signal hits surface to top with "🔥 HOT" badge
- Summary of what triggered the urgency (from Signal Hit relevance assessment)

### New "Tracking" page (offering-scoped)
- All companies across all campaigns currently flagged as hot
- Grouped by signal type (e.g. "3 companies hiring for relevant roles", "2 companies announced funding")
- Each row links to campaign + Deep Research view
- Last scan timestamp + next scheduled scan
